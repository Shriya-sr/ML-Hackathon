# Methodology

This document describes *how* PathSnap works and why each decision was taken. Numbers quoted in the report
are generated by the scripts listed at the end and stored under `experiments/` and `reports/`.

## 1. Data relationships

```
.track  (fix i: lon, lat, t)                 GPS observations, ~1 Hz
   │  no row correspondence with anything below
   ▼
candidate generation (spatial query)         fix i  ->  K nearby arcs
   │
.arcs   (arc_id = row: from_node, to_node)   directed straight segments
   │
.nodes  (node_id = row: lon, lat)            segment end points
   │
.route  (ordered arc_ids)                    reference path, ~1 arc per 5 fixes
```

`.route` has fewer rows than `.track` and is a chain of arcs, so **per-fix labels must be derived**
(Section 3). Node ids and arc ids are separate index spaces; the code never mixes them. `RoadNetwork.u/v`
map arc → node, and `reverse_arc` maps an arc to its opposite direction.

## 2. Preprocessing (`src/pathsnap/data/preprocessing.py`)

* Drop rows with non-finite or out-of-range coordinates/timestamps (none occur in the supplied data, but
  the evaluator data might contain them).
* Stable re-sort by timestamp; remove duplicate timestamps (keep first). `orig_index` maps every cleaned
  fix back to its raw row.
* **Projection** (`geography/projection.py`): trips are spread over the whole world, so each trip is projected into
  the UTM zone of its own centroid (EPSG 326xx/327xx). Within a zone the scale error is < 0.1%, far below GPS
  noise. All distances, bearings and speeds are computed in these metres, never in degrees.
* GPS gaps (dt > 30 s) are flagged; the HMM breaks its chain for dt > 120 s.

## 3. Per-fix labels by monotone alignment (`data/labeling.py`)

For fix i and route position j the cost is

```
cost(i, j) = min(dist(fix_i, arc_route[j]), 100 m) + 15 m * (1 - cos(motion_i, direction_j)) / 2
```

and we want positions j_0 ≤ j_1 ≤ … ≤ j_N-1 (the vehicle never goes backwards along its own route)
that minimise the total cost. Dynamic programming solves this exactly:

```
C[i, j] = cost(i, j) + min_{j' ≤ j} C[i-1, j']
```

(prefix minima make each row O(M); total O(N·M)). The heading term separates the two directions of a
road on out-and-back trips, where both arcs have identical geometry. Fixes whose aligned arc is more than 60 m
away (mainly vehicles parked off-network, e.g. in car parks) get label −1 and are excluded from training rows
and from accuracy denominators. Labels are used **only** to mark candidates as correct for training
and to score predictions on the server.

## 4. Candidate generation (`features/candidate_generation.py`)

* All arcs are inserted as straight segments into a Shapely **STRtree** (R-tree). One vectorised
  `dwithin` query returns every (fix, arc) pair within R metres, so there is no full-network scan per fix.
* Keep the K nearest per fix; if none lies within R, take the single nearest arc within 150 m (fallback).
* R = 50 m, K = 10 were chosen from the training-partition sweep (`reports/eda/candidate_radius_sweep_train.csv`).
  Below 35 m the miss rate rises sharply. Above 50 m the gain is small while candidates per fix grow
  (more work for the classifier and HMM).
* **Candidate miss rate** = share of labelled fixes whose reference arc is not among their candidates.
  This is a hard ceiling for any downstream model and is reported everywhere. The ground-truth arc is
  **never** inserted into the candidate list.

## 5. Features (`features/feature_extraction.py`, schema in `feature_schema.py`)

21 features in five groups. Nothing is learned during feature extraction, so features cannot leak across
partitions. Scaling for LR/KNN/SVM/MLP happens inside each model's Pipeline, fitted on training folds only.

| Group | Features | Rationale |
|---|---|---|
| geometric | dist_m, dist_rank, dist_minus_min, dist_ratio, n_candidates, proj_frac, at_endpoint, endpoint_dist_m, arc_length_m | closeness relative to the other candidates matters more than absolute distance |
| heading | cos_heading, heading_diff_deg, heading_valid, cos_long_bearing | separates the two directions of a two-way road and crossing streets |
| context | win_mean_dist_m, win_max_dist_m (±3 fixes) | a road that fits the neighbouring fixes too is more plausible than one that fits a single noisy fix |
| kinematic | speed_mps, dt_prev, dt_next | heading reliability depends on speed; gaps reduce context reliability |
| network | from_in_degree, to_out_degree, is_two_way | junction structure and one-way roads |

Feature value is checked by permutation importance and group ablation on training folds
(`scripts/feature_analysis.py`).

## 6. Supervised candidate classification

* Unit = (fix, candidate arc) row, target = 1 if the arc is the fix's reference arc.
* Training rows: every 2nd labelled fix of the training trips (1 Hz fixes are strongly autocorrelated; this
  halves cost with negligible information loss). Validation/test rows: **all** labelled fixes.
* **Validation**: 5-fold `GroupKFold` with group = trip_id (shuffled, seed 42). All rows of a trip are in one fold,
  so CV measures generalisation to unseen trips (and cities).
* Eight models from seven families were trained with identical features and folds:
  LR, Gaussian NB, KNN, Random Forest, Extra Trees, HistGradientBoosting, RBF-SVM (Platt), MLP.
  KNN and SVM use trip-stratified subsamples of the training rows (60k / 20k) because their cost grows
  super-linearly. This is recorded in `configs/models.yaml`.
* **Metrics**
  * candidate level (threshold 0.5): accuracy, precision, recall, F1 (positive and macro), log loss, ROC-AUC, Brier, confusion matrix
  * fix level: **Top-1 accuracy** (highest-probability candidate equals the reference arc; fixes with a missed or no
    candidate count as errors)
  * route level: see Section 9
* **Primary selection metric**: mean CV Macro-F1. Candidate rows are imbalanced (184,089 of 1,246,339 training rows,
  14.8%, are the correct road), so plain accuracy is dominated by the wrong-road class; Macro-F1 weights both classes equally and
  penalises missed true segments and false matches alike. It is read together with CV Top-1
  (the map-matching objective), log loss (probability quality, which matters because probabilities feed the HMM
  emissions), fold stability and computational cost. Training accuracy is never used for selection.

## 7. Bayesian optimisation (`optimisation/`, `scripts/optimise.py`)

* Optuna **TPE** sampler (seed 42, 10 random start-up trials), **MedianPruner** on per-fold running means.
* Objective: mean Macro-F1 over the *same* 5 trip-grouped folds of the 80 training trips (search uses every 4th fix
  for speed; the winner is re-scored with the baseline protocol).
* Search space (HistGradientBoosting): learning_rate 0.02–0.3 (log), max_iter 100–800, max_leaf_nodes 15–127 (log),
  max_depth {None, 6, 10, 16}, min_samples_leaf 10–400 (log), l2_regularization 1e-4–10 (log), max_features 0.5–1.0.
  These cover capacity (leaves/depth/iterations), step size and regularisation, which control the bias-variance
  trade-off.
* Tuned vs untuned are compared on identical folds and the identical 10 student-test trips. The final variant is
  chosen by **CV** Macro-F1, never by the student-test score.

## 8. HMM and Viterbi (`decoding/`)

* **Hidden states** at fix t: its candidate arcs (top 8 by emission). Each state carries arc_id, projection fraction,
  distance and classifier probability, so the state → arc mapping is never lost.
* **Emission**: `log E = w_clf · log max(P_clf, 1e-6) − w_dist · ½ (d/σ)²`.
* **Transition** (a at t−1 → b at t): driving distance `d_route` by bounded Dijkstra over the directed graph,
  compared with the straight GPS displacement `d_gps`:
  `log T = −|d_route − d_gps| / β − uturn_penalty·[b = reverse(a)]`.
  Transitions are **impossible (−∞)** if b is unreachable within the search radius (disconnected, or the wrong
  way along one-way arcs) or the implied speed exceeds 55 m/s.
* **Viterbi**: log-space max-product recursion with back-pointers, over variable-size state sets.
* **Fallbacks, which never fabricate segments**:
  * fix with no candidates → no prediction there; a new chain starts after it
  * all transitions −∞ → a new chain starts at that fix (`no_valid_transition`)
  * dt > 120 s → a new chain starts (`gps_gap`)
  * empty sequence → empty output; single fix → argmax emission
* **Route reconstruction**: inside a chain, consecutive distinct arcs that do not touch are joined by the shortest
  network path, which is exactly the path the transition model scored. Across chain breaks nothing is inferred
  and the gap stays visible.
* Decoder parameters (w_clf, β, w_dist, uturn_penalty) are grid-searched on 30 **training** trips using
  **out-of-fold** probabilities, so each trip is scored by a classifier that never saw it.

## 9. Route-level metric definitions (`evaluation/route_metrics.py`)

* predicted route = per-fix arcs in time order, consecutive repeats collapsed (or the reconstructed route)
* **route continuity** = share of consecutive route pairs (a, b) with `to_node(a) == from_node(b)`
* **invalid transitions** = number of pairs that are not connected
* **route precision / recall / F1** = length-weighted overlap of predicted and reference arc sets
* **missing / extra segments** = reference arcs never predicted / predicted arcs not in the reference
* **edit similarity** = 1 − Levenshtein(pred, ref) / max(len) on arc sequences, which penalises wrong order,
  missing and extra arcs
* **LCS recall / precision** = longest common subsequence / len(ref) (resp. len(pred))
* **selection Macro-F1** = Macro-F1 of the decision "selected candidate = 1, others = 0" over candidate rows.
  This lets classifier-only and HMM outputs be compared on the same rows, because the HMM produces no
  threshold-able scores.

## 10. Leakage controls

| Risk | Control |
|---|---|
| fixes of one trip in train and validation | GroupKFold by trip_id; partitions are separate folders |
| reference used at inference | `load_trip(with_route=False)` on the prediction path; candidate generation tested to be identical with/without labels |
| learned preprocessing fitted on test | only scalers inside Pipelines, re-fitted per training fold |
| feature selection on test | permutation importance / ablation on training folds only |
| hyperparameter or decoder tuning on test | Optuna and HMM grid use training trips only; student-test scored once afterwards |
| evaluator data | arrived after development; never read by any training/tuning script; scored once by `scripts/evaluate_heldout.py` with frozen artifacts; the API scores it server-side and returns aggregates only |
