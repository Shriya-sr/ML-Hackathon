# Contributing

## Branches

* `main`: stable, demo-ready. Only merged from `develop` after tests pass.
* `develop`: integration branch.
* `feature/<area>` (e.g. `feature/hmm-viterbi`, `feature/frontend`): one topic per branch, merged into
  `develop` through a pull request.

## Commits

Conventional commits: `feat(scope): …`, `fix: …`, `test: …`, `docs: …`, `refactor: …`, `chore: …`.

Before every commit:

1. `git diff --staged`: review what you are committing.
2. `python -m pytest -p no:warnings` and `cd frontend && npx vitest run`.
3. Never commit `.env`, credentials, `data/raw/`, `data/processed/`, `.venv/`, `node_modules/` or
   `artifacts/models/experiments/` (all in `.gitignore`).
4. Never commit evaluator-trip files or anything derived from their reference routes.

## Reproducibility rules

* All randomness uses seed 42 (`pathsnap.config.SEED`).
* Results and figures are generated by scripts in `scripts/` from saved experiment records. Never edit numbers
  by hand in reports.
* Changing labelling, candidates or features means re-running `build_features.py` and every downstream script.
